### 第四轮 · 整点前后的两次访问

**8 · 中 · 单用户顺序访问也可能遇到整点 500。** 当上一个小时一直无人访问，其首次读取可能恰好在整点前写入；新小时首个读取随即写同一个键。Cloudflare 对 Workers KV 的同键写入限制为每秒一次。`api-worker/src/sin-die.js:16` 等待写入完成，限流异常进入 `src/index.js:177`，调用端收到通用 500。[Cloudflare KV 写入限制](https://developers.cloudflare.com/kv/platform/limits/)

在独立 Node 进程调用实际 `worker.fetch`，沿用项目测试身份替身。内存 KV 初始为空，给它加上“距上次成功写入不足 1000 毫秒则抛错”的限制。三次请求均等待上一次结束后才发出。

| 访问时间（JST） | 本地响应 | KV 结果 |
| --- | --- | --- |
| 14:59:59.850 | 200，14 时结果 | 首次写入成功 |
| 15:00:00.050 | 500，`internal_error` | 新小时写入遇到模拟限流 |
| 15:00:01.050 | 200，15 时结果 | 重试写入成功 |

**复验要求。** 保留单键和命中直接返回的设计，覆盖这个 200 毫秒边界。若在请求内重试，应复用已经确定的小时结果并限制重试次数；不得把未写成功的随机结果当作已稳定的缓存结果返回。该实验验证错误处理路径，生产发生频率未测量。

**旧项 1、2 复核。** 同小时并发冷读仍返回 I 和 II。另在无写入节流的内存 KV 中，暂停 14:59:58 请求的写入，让 15:00 请求先写并返回 IV，再放行旧请求。缓存被退回 14 时，15:00:03 又生成 V。这是旧项 1 的另一种触发顺序，修复时应同时验证“较旧小时不能覆盖较新小时”。KV 还有跨位置读到旧值的可能性，本次没有测量真实边缘节点。断档用例亦再次复现旧项 2：11 月 19 日的两个相同结果仍影响 11 月 21 日的首掷，待确认历史口径。[Cloudflare KV 一致性说明](https://developers.cloudflare.com/kv/concepts/how-kv-works/)

### 第五轮 · 逐帧核对骰面可见性

**9 · 中 · 飞行时会漏画本应可见的骰面。** `public/tools/sindie/game.js:28` 使用有限距离的透视相机，而第 108 行始终以固定镜头方向剔除面。骰子靠近屏幕边缘时，某个面朝向相机所在点，仍可能被跳过；这影响骰体外观，内核决定的罪名不受影响。

复验使用实际 `motion.js`。视口 375×812，初始姿态 `restPose(faces[0], .12)`，掷出 I，动画随机源固定为 0.33。在点击后第 23/60 秒，第 0 面的四个顶点投影约为 (40,682)、(32,759)、(45,786)、(57,790)，全部在屏内，面积约 1,205 平方 CSS 像素。现有判定的点积为 −0.0213，会跳过该面；用世界坐标的“相机位置减面中心”判定，点积为 +3.1879。审核意见是令剔面与投影使用同一相机，沿用现有凸体绘制即可。复验应覆盖侧边飞行帧及落定帧。

旧项 3 再次测得收手交界骰心从 (188,755) 跳到 (−19,798)。旧项 6 的七组上下同索引面仍全部异名，七种罪名各占两面仍成立。两者与本轮剔面问题可分别验证。

### 第六轮 · 仅用键盘重掷，再切换屏幕方向

**10 · 中 · 用键盘完成首掷后，焦点丢失。** 在全新 Chrome 会话用 Tab 聚焦“掷骰”，按 Enter。投掷期间 `game.js:158` 禁用按钮，落定后第 66 行重新启用。此时实测 `document.activeElement` 为 `BODY`，再次按 Enter 仍停在 reveal，必须重新导航到按钮。审核意见是保持键盘连续投掷能力，同时避免把投掷期间已经移到返回链接的焦点抢走。验收可分别操作“Enter → 等待 → Enter”和“投掷中移焦 → 等待”。

同一浏览器另行复验了旧项 4、5。812×375 下牌匾仍占 y=126–237；第二掷期间可访问性树仍保留上一掷的“V / GVLA / 暴食”。在该掷进行中把视口转为 375×812，完成后正常显示新结果“傲慢”，页面宽度为 375，没有水平滚动。旧项 7 对照同一版设计第 3 行复核，备忘录记录仍缺失。以上交互与几何修正均可沿用现有按钮、画布和页面结构。
