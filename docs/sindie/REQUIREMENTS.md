# 告解骰 · 需求

## 用户原话

2026-11-21 JST：

> 照着刚才的七大罪骰子，设计一个有宗教信仰的圣洁和古老陈旧感并存的小游戏，这个小游戏就是单纯的投掷一个骰子，不完全随机，每次必然不一样，先出结果不展示，骰子的抛出，旋转等都是既有结果的动画。参考一半骰子游戏的动态感进行设计。界面简单但是强调氛围感。另外需要带一个api接口采用同样的内核，每小时只会刷新一次内容，短时间内的访问指挥从kv缓存中直接返回结果。

> 注意和其他minitool一样需要部署在主站挂在饰品铺子小游戏队列，但是api是单独部署给subscription-api的worker的

> （截图）subscriptions-api 的绑定里已有 KV `kvforapi` → `stock-data`。

> 骰子面交给你决定，对应换下拉丁字，从美德换成罪名；原则上三次roll点几乎不会完全一样，如果发生了，就roll6

说明：没有找到「七大罪骰子」的源文件，用户把骰面交给本次设计决定。

## 规则

| 项 | 规则 |
| --- | --- |
| 骰子 | 一颗 D14（七边形偏方面体，形如圣物宝石），七大罪各占两面，上下半各一面。朝上的那一面就是结果 |
| 骰面 | 按中世纪 SALIGIA 顺序：I SVPERBIA 傲慢、II AVARITIA 贪婪、III LVXVRIA 色欲、IV INVIDIA 嫉妒、V GVLA 暴食、VI IRA 暴怒、VII ACEDIA 懒惰。骰面刻罗马数字，揭示时显示拉丁罪名、中文名和圣徽 |
| 内核 | 七面等概率。如果这一掷和前两次连成三次相同，就改从另外 6 面里等概率重抽（解释：「roll6」理解为从剩下 6 面重抽）。随机数用 `crypto.getRandomValues` |
| 先定后演 | 点击后先由内核定出结果，不显示；抛出、飞行、弹跳、翻滚、晃动、落定全是落到既定面上的动画。落定后再揭示结果 |
| 动态感 | 参考常见骰子游戏：从手边抛入、受重力的抛物线、逐次衰减的弹跳、翻滚减速、最后在棱上晃动后倒向结果面，落地有尘埃，第一次落地轻微震屏 |
| 氛围 | 圣洁与古旧并存：穹顶下的石砌祭坛、自上而下的光柱、浮尘、烛火、金箔、风化石纹、拉丁铭文。界面元素极少 |
| 页面历史 | 页面只在内存里记最近两次结果，刷新后重置（用户已同意「各算各的」） |
| 入口 | 和月下秘仪一样，挂在饰品铺子「小游戏」分组，进入全屏页 `/minitools/tools/sindie/`，左上角「← 饰品铺子」返回 |
| API | 部署在 subscriptions-api Worker：`GET /api/v1/sin-die`，沿用该 Worker 现有的 Access 鉴权。按东京时间整点刷新：同一小时内直接返回 KV 里的结果，跨小时才用内核掷新一次（历史为前两个小时的结果）并写回 KV |
| KV | 用已有绑定 `kvforapi`（命名空间 `stock-data`），只用一个键 `sindie:hour:v1` |
| 同一内核 | 内核是一个独立的小文件，原样复制到 API Worker，记录来源和 SHA-256 |

## 不包含

- 页面不调用 API，也不显示「本小时之罪」。
- 不存掷骰历史和统计，不做音效、分享、多颗骰子、设置项。
- API 不提供强制刷新、写入或删除。

## 验收要点

1. 连续掷 1000 次（单测），任意连续三次都不相同；七面都会出现。
2. 动画结束时朝上的面与预先定好的结果一致；揭示前页面上没有结果文字。
3. 桌面和手机宽度都无横向滚动，动效始终开启。
4. API：同一小时多次请求返回同一结果且不重新计算；跨小时会变化，并遵守三连规则；KV 只写 `sindie:hour:v1`。
5. 部署 subscriptions-api 后 `kvforapi` 等现有绑定仍在。
